# Learning — what the kit remembers in a project, and how

The kit learns from its own mistakes and from the user: their terms, style and habits. Nothing is
learned silently: observations are collected, `/tl-retro` turns them into proposals, the user approves
them. The memory is local (`.claude/tl-memory/learn/`, hidden from git, kept by kit updates); only the
glossary is shared with the team (`/tl-retro share`). Tool: `python .claude/tech-lead-kit/scripts/tl_learn.py`.

## Files in `.claude/tl-memory/learn/`
| File | What | Language | Written by |
|---|---|---|---|
| `INBOX.md` | raw observations, one line each: `- [ ] date · kind · scope · what happened · source` | Russian | `tl_learn.py note` / `harvest`; `/tl-retro` ticks `[x]` |
| `LESSONS.md` | `## L-001 · active · <scope>` + `- Когда:` / `- Правило:` / `- Почему:` (evidence: "видели N×", dates) | Russian | `/tl-retro` after approval |
| `PROFILE.md` | the user: sections `## Общение`, `## Привычки`, `## Постоянные ответы`; one `- ` item each, ≤ 12 items | Russian | `/tl-retro` |
| `GLOSSARY.md` | table `| מונח | משמעות | איפה בקוד ובנתונים |` — the user's word as they write it | Hebrew | `/tl-retro`; after `share` the published copy is the master |
| `ACTIVE.md` | generated by `tl_learn.py render`, ≤ 60 lines; imported by CORE, so always in context | English + content | never by hand |

Project skills: `.claude/skills/tlp-<slug>/SKILL.md` from `.claude/tech-lead-kit/templates/project-skill.md`.
The installer never removes them (it removes only `tl-*`); uninstall moves them to
`tl-memory/skills-disabled/`, the next install brings them back.

## Kinds and scopes
- Kinds: `correction` (the user corrected or rewrote the result), `mistake` (a check found the kit's own
  error), `term`, `style` (language, length, format of replies), `habit` (the same choice again, a standing
  answer), `procedure` (the same multi-step work again), `kit` (the kit itself got in the way — for its author).
- Scopes: `kit`, `project`, `route:/tl-sql`, `skill:<name>`, `agent:<name>`, `area:<topic>`.
- Statuses of a lesson: `active` (in `ACTIVE.md`), `rejected` (keep it: never propose it again without new
  evidence), `retired` (no longer true). Lessons are never deleted.

## Rules
- **CORE wins.** A lesson may only add or narrow a rule. Never: skip tests, standards or approval, commit or
  push, write on PROD, change the language of comments and documents. `tl_learn.py lint` rejects these.
- **No secrets or personal data** in any memory file: no passwords, connection strings, host names, e-mails,
  phone or id numbers, names of customers. `note` and `harvest` refuse them; write the rule, not the value.
- **One event is evidence, not a rule.** A proposal shows how often it was seen; the user decides.
- **Applied without a question** (and listed in the report): only reply length, reply format and the chat
  language, when the user asked for them directly. Everything else waits for the user's yes.
- An explicit "remember …" / "запомни …" / "תזכור …" from the user is an approval: write it at once.
- **Budgets** (`ACTIVE.md` is in every conversation): ≤ 30 active lessons, ≤ 12 profile items, terms fill
  the rest of 60 lines. Over budget → `/tl-retro` proposes to merge or retire.
- A project skill only for work seen ≥ 3 times with the same steps; it names its sources and stays inside
  the kit rules (it uses kit scripts and skills, it does not replace them).

## Harvest — observations nobody noted
`tl_learn.py harvest [--days 14]` reads what is already on disk and adds new lines to `INBOX.md`:
Claude Code transcripts of this project (`~/.claude/projects/<project>/*.jsonl`: corrections in the user's
messages, the reason of a rejected tool call, the message after an interrupt), notes of Claude Code's own
auto memory (turned off by `/tl-init`), failed and timed-out queries in `sql-journal.csv`, and the same
answer to the same question in several specs ("הבהרות"). It only proposes; the transcript format belongs to
Claude Code and may change, so a missing source is not an error.
