# Что нового в Tech Lead Kit

## 2.3.0 — 2026-10-19
- **Чужие агенты тоже под запретом — только в этом проекте.** Агенты из `~/.claude/agents/`,
  включённых плагинов и проекта, которые не из kit (например, свой «SQL-эксперт» или
  «планировщик»), видят CLAUDE.md, но не имеют skills kit, а их промпт может противоречить kit.
  `tl_doctor` их находит, `/tl-init` спрашивает и запрещает в личном `.claude/settings.local.json`
  (`--keep-agent <имя>` — оставить нужного). Глобальные файлы и другие проекты не меняются.

## 2.2.0 — 2026-10-19
- **Только агенты kit.** Встроенные агенты `Explore` и `Plan` запускаются без CLAUDE.md (не видят
  правил kit), у `general-purpose` нет skills kit. `/tl-init` (`tl_doctor.py --apply-settings`)
  запрещает их в личном `.claude/settings.local.json` (скрыт от git) — работу берут агенты `tl-`,
  которые загружают CLAUDE.md и свои skills. `tl_doctor` предупреждает, если запрета нет.
- `tl-researcher` получил режим `search` — замена встроенному Explore. Мелкий поиск (до ~5 файлов)
  Claude делает сам, без агента. В KIT_GUIDE — таблица «какой агент для чего».
- Глобальный `~/.claude/CLAUDE.md` kit не меняет (он действует во всех проектах); `tl_doctor`
  только сообщает о противоречиях в нём.

## 2.1.0 — 2026-10-19
- **Новое окно установки:** таблица проектов (версия, статус «актуально / обновить / не
  установлен», режим документов); проекты добавляются папкой, **поиском проектов на диске**
  (папки с `.git`), из **недавних папок VS Code**, перетаскиванием или вставкой пути; удаление kit
  из проекта, «Открыть папку», прогресс установки. Окно запоминает последние папки.
- **`tl_sql.py`** — шлюз к базам: `check` проверяет запрос до отправки (запись на PROD, нет
  ограничения строк, `SELECT *`, функция на колонке фильтра, `LIKE '%…'`, декартово
  произведение, скан большой таблицы без индекса по кэшу схемы); `guard` добавляет защиту для
  MCP; `run` выполняет через `sqlcmd` / DB2 CLP с **жёстким таймаутом** (зависший клиент
  останавливается), сохраняет CSV и журнал; `schema` ищет таблицы и пути JOIN в кэше схемы.
- **Агент `tl-dba`** — исследует размеры, статистику, планы и блокировки и даёт минимум три
  варианта решения с выигрышем, ценой и риском (`/tl-sql tune`, вопросы объёма в анализе).
- **Графики в отчётах:** `an_chart.py` строит офлайн SVG (столбцы, линии, полоса границ, линия
  цели) из CSV результата запроса.
- **Проверка стиля документов:** `tl_knowledge.py style` — слова без чисел, заглушки, пустые
  разделы, «вода»; `check` показывает это перед публикацией (совет, не блокирует).

## 2.0.0 — 2026-10-19
- **Навигатор `/tl-go`.** Пишешь, что нужно, своими словами — kit предлагает маршрут, ты
  подтверждаешь кнопкой. Без слов — показывает незаконченную работу и следующий шаг.
  `/tl-go new <просьба>` ведёт новую задачу от одной строки до кода, останавливаясь только на
  утверждениях.
- **Уровни глубины:** `mvp` (один короткий документ, одно утверждение, код с тестами главных
  сценариев), `standard`, `full`. Лишние проверки убраны: каждая делается один раз.
- **Требование вместе с тобой:** `/tl-spec new` — интервью по разделам, `/tl-spec complete` —
  дополнить существующее. Вопросы — кнопками, с рекомендованным ответом.
- **План задач с галочками** в дизайне (или в MVP-документе): `/tl-implement` продолжает с места
  остановки в новой сессии. `FLOW.md` в папке задачи — где ты в процессе.
- **SQL:** `/tl-sql build | check | tune`; DBA ищет варианты решения по размеру и причине.
- **Не зависать:** лимиты времени для MCP (`/tl-init` ставит их), защита в каждом запросе
  (`LOCK_TIMEOUT`, `QUERY_GOVERNOR_COST_LIMIT`, `WITH UR`), «проба → расширение», бюджеты и
  `maxTurns` у агентов, пределы всех циклов.
- **Любая тема, любая база:** реестр источников данных (`data-sources.json`) вместо двух
  зашитых серверов; MCP или командная строка.
- **`/tl-explain`** — объяснения и документ проекта со схемами (вместо прежней команды
  tl-project-doc). `/tl-an learn` вместо прежней tl-an-learn.
- Стандарт письма без «воды» (`WRITING.md`); проверка цифр аналитика перед выводом.
- Установщик при обновлении удаляет старые файлы kit (переименованные команды не остаются).
- Встроенный `/init` не нужен — `/tl-init` делает это сам.
