# Tech Lead Kit для Claude Code

Набор файлов для Claude Code (VS Code extension), который заставляет Claude работать
**как Tech Lead вместе с архитектором, аналитиком и DBA**, а не как junior: понять задачу,
описать требование, спроектировать, написать код малыми шагами с тестами, проверить.
Глубина процесса — по задаче: от быстрого MVP до полного пути с проверкой на данных.

- Без плагинов и без hooks: только обычные файлы в папке `.claude/` проекта.
- Переносится на USB, ставится одним скриптом `install.cmd` (Windows 11).
- Устанавливается **только в выбранные проекты** и скрыт от git: сам kit в репозиторий
  компании не попадает. В проект попадают только **утверждённые документы**, и только когда ты
  сам их публикуешь (`/tl-publish`).
- Подходит для любой темы и любого проекта. Базы данных — через источники, которые `/tl-init`
  находит в проекте (MCP-серверы или клиенты командной строки) и записывает в реестр: Claude
  проверяет **реальную** схему, таблицы и индексы, а не угадывает их.

Языки и платформы: C#/.NET, C++, Python, Node.js, COBOL, Natural, микросервисы, web services,
SQL Server 2019/2022, DB2 for z/OS, stored procedures.

> **Путеводитель со схемами:** [`docs/GUIDE.html`](docs/GUIDE.html) (русский) и
> [`docs/GUIDE.he.html`](docs/GUIDE.he.html) (иврит). Открой файл в браузере
> (двойной клик), интернет не нужен.

## С чего начать: одна команда
После установки и `/tl-init` достаточно помнить одну команду — **`/tl-go`**:
- `/tl-go <что нужно, своими словами>` — kit предлагает подходящий маршрут (или цепочку) и
  спрашивает подтверждение кнопкой;
- `/tl-go` без слов — где ты остановился: незаконченные задачи, документы, которые ждут
  утверждения, следующий шаг;
- `/tl-go new <просьба>` — новая задача от одной строки до кода: требование → (дизайн) → код →
  проверка, с остановками только для твоего утверждения.

Пример: `/tl-go new построить микросервис, который выдаёт чеки по счёту и периоду`.

## Маршруты — у каждого одна цель
| Маршрут · команда | Когда | Режимы | Что получаешь |
|---|---|---|---|
| Навигатор `/tl-go` | не знаю, какой командой; где я остановился | просьба словами · без слов · `new` | нужный маршрут после твоего «да» |
| Подготовка `/tl-init` | первый раз в проекте и после обновления kit | — | проверка kit, лимиты времени, карта проекта, источники данных |
| Требование (אפיון) `/tl-spec` | есть просьба бизнеса — что именно делать? | `new` — пишем **вместе** (интервью по разделам) · `complete SPEC-nnn` — дополнить вместе · `SPEC-nnn` — kit собирает сам · `check <файл>` — проверить чужую | `SPEC.md` + `SPEC.html`, стоп на утверждение |
| Технический дизайн `/tl-design` | большое изменение: **как** построить — варианты, цена, риски, выбор | `SPEC-nnn` или задача | дизайн, ADR, план задач с галочками; стоп на утверждение |
| Код `/tl-implement` | написать или исправить код | задача · `SPEC-nnn` · путь к дизайну | код + тесты (каждый сценарий приёмки → тест); продолжает с места остановки |
| SQL `/tl-sql` | запросы, процедуры, индексы | `build` по требованию · `check` правильность и корректность · `tune` медленный запрос: варианты от DBA | SQL с путём доступа / отчёт проверки |
| Проверка кода `/tl-review` | код готов — проверить перед git / коллегами | файлы или текущие изменения | замечания BLOCKER/MAJOR/MINOR + покрытие требований тестами |
| Анализ `/tl-an` | что говорят цифры; стоит ли идея; код делает то, что нужно? | `learn <тема>` · задача · `verify SPEC-nnn` | отчёт с числами и вердиктом |
| Объяснение `/tl-explain` | как устроено X; документ проекта | `project [модуль]` · `<что объяснить>` | HTML со схемами + Markdown |
| Здоровье кода `/tl-debt` | что плохо в коде и что чинить первым | путь / модуль | реестр долга с приоритетами |
| Публикация `/tl-publish` | отдать утверждённые документы команде | — | `docs/` + блок в `AGENTS.md`; commit делаешь ты |

Встроенный `/init` Claude Code **не нужен**: `/tl-init` делает то же глубже и локально, а общий
файл для команды — `AGENTS.md` через `/tl-publish`.

## Уровни глубины: быстро и хорошо, без лишней работы
| Уровень | Когда | Что делается | Утверждений |
|---|---|---|---|
| `mvp` | нужно быстро получить работающее | один короткий документ «требование + решение + план» → код с тестами главных сценариев → проверка кода (только BLOCKER) | одно |
| `standard` | обычная доработка | требование → дизайн, если изменение большое → код → проверка кода | 1–2 |
| `full` | деньги, правила решений, PROD-данные | всё: эффект на истории, критики, проверка эффекта после | 2 + вердикт |

Каждая проверка делается один раз. То, что отложено ради скорости, записывается задачей в план
или в `TECH_DEBT.md`.

## FLOW новой задачи

`FLOW.md` — чек-лист этапов. Каждая команда отмечает свой этап, `/tl-go` по нему показывает,
где ты и что дальше.

| # | Этап | Команда | Skills | Агенты | Результат | Остановка |
|---|---|---|---|---|---|---|
| 0 | Вход | `/tl-go` | — | — | маршрут и уровень, `FLOW.md` | подтверждение |
| 1–3 | Приём, изучение, уточнение | `/tl-spec` | `tl-requirements`, `tl-sql-engineering` | `tl-researcher` | `REQUEST.md`, `NOTES.md`, «הבהרות» | вопросы кнопками |
| 4 | Требование | `/tl-spec` | `tl-requirements` (+ `tl-analytics` на `full`) | `tl-spec-skeptic` (если есть числа/правила) | `SPEC.md` + `SPEC.html` | **утверждение** |
| 5 | Дизайн (большое; на `mvp` — часть `SPEC.md`) | `/tl-design` | `tl-architecture` | — | дизайн, ADR, план задач | **утверждение** |
| 6 | Код | `/tl-implement` | `tl-engineering-standards`, `tl-sql-engineering` | — | код + тесты, галочки в плане | 3 неудачи на тест → стоп |
| 7 | Проверка кода | `/tl-review` | `tl-engineering-standards`, `tl-tech-debt` | `tl-architect-reviewer`, `tl-sql-reviewer` | замечания + покрытие | выбор кнопкой |

| 9 | Публикация | `/tl-publish` | — | — | `docs/`, `AGENTS.md` | commit — твой |

## Не зависает и не крутится вечно
- **Лимиты времени MCP.** По умолчанию Claude Code ждёт ответа MCP до ~28 часов, а вызовы из
  субагентов не уходят в фон — медленный запрос выглядит как зависание. `/tl-init` (через
  `tl_doctor.py --apply-settings`) записывает лимиты в `.claude/settings.local.json` (личный файл).
- **Защита в каждом запросе:** SQL Server `SET LOCK_TIMEOUT` и `QUERY_GOVERNOR_COST_LIMIT`
  (тяжёлый запрос отклоняется до запуска), DB2 `FETCH FIRST … WITH UR`; сначала размер из
  каталога, потом маленькая проба, потом расширение.
- **Бюджеты и пределы:** у агентов `maxTurns` и бюджет запросов, у каждого цикла (вопросы,
  исправление запроса, критик, красный тест, ревью) — предел; на пределе Claude останавливается
  и честно говорит, что сделано и что осталось.
- **`tl_sql.py`**: каждый запрос сначала проверяется (`check`: запись на PROD, нет ограничения
  строк, функция на колонке фильтра, скан большой таблицы без индекса); через клиент командной
  строки (`sqlcmd`, DB2 CLP) запрос идёт с **жёстким таймаутом** (`run`) — зависший клиент
  останавливается, результат сохраняется в CSV.
- Если запрос всё же завис: Stop / Esc, затем `/tasks`; на сервере запрос может продолжаться —
  попроси DBA завершить сессию.

### Знания видны всем агентам
- Каждый документ kit начинается со строки `tl-meta` (тип, статус, дата, **область**). Скрипт
  `tl_knowledge.py index` собирает из них `KNOWLEDGE.md`, и в начале **любой** задачи Claude
  открывает документы своей области. Утверждённая אפיון и принятый ADR обязательны.
- `/tl-publish` переносит утверждённые документы в `docs/` проекта и пишет в `AGENTS.md` блок
  «ידע על הפרויקט» (в `CLAUDE.md` добавляется строка `@AGENTS.md`). Так документы видят коллеги
  без kit и любые агенты. Commit делаешь ты.

### Kit, а не что-то другое
- **Перед первой правкой кода** Claude загружает `tl-engineering-standards` и файл правил языка,
  даже для мелкой правки и без команды. Для исследования, ревью и критики — агенты `tl-`.
- **Только агенты kit.** Встроенные агенты `Explore` и `Plan` запускаются **без CLAUDE.md** (не
  видят правил kit), у `general-purpose` нет skills kit. Агенты kit загружают CLAUDE.md и свои
  skills. Поэтому `/tl-init` записывает в личный `.claude/settings.local.json` (скрыт от git)
  запрет встроенных агентов (`"deny": ["Agent(Explore)", "Agent(Plan)", "Agent(general-purpose)"]`)
  и **всех агентов не из kit** — из `~/.claude/agents/`, плагинов и проекта (например, свой
  «SQL-эксперт» или «планировщик»): CLAUDE.md они видят, но skills kit у них нет, а их собственный
  промпт может противоречить kit. Запрет действует **только в этом проекте**; в других проектах
  эти агенты работают. Оставить нужного: `/tl-init` спросит, или `--keep-agent <имя>`.
  Это обычное правило доступа, а не hook. Поиск по нескольким файлам Claude делает сам, широкий
  поиск — `tl-researcher` (режим `search`). Глобальный `~/.claude/CLAUDE.md` kit не меняет: он
  действует во всех проектах, а в проекте с kit загружается **вместе** с правилами kit (не вместо
  них); `tl_doctor` сообщает о противоречиях в нём, и Claude спрашивает, какое правило главное.
- `/tl-init` запускает `tl_doctor.py`: kit подключён и скрыт от git; чужие skills, агенты,
  команды, `CLAUDE.md`, MCP-серверы, плагины и hooks, которые могут перехватить работу; базы,
  не внесённые в реестр; лимиты времени. Чужие файлы Claude не правит — спрашивает тебя.

## Правила работы (кратко)
- **Маршрут, уровень и размер называются в начале.** Большое изменение (новый модуль/сервис,
  схема БД, интеграция, больше 3 файлов) — только после дизайна и **твоего утверждения**.
- **Язык:** Claude отвечает на русском. Комментарии в коде и документы (אפיון, ADR, дизайн) —
  на иврите; для мейнфрейма — только если кодировка поддерживает.
- **Базы:** только через источники из реестра. PROD только на чтение. На TEST изменения
  разрешены, но Claude показывает команду заранее, а для разрушающих нужно твоё подтверждение.
  Неизвестная среда считается PROD.
- **Вопросы** — кнопками, с рекомендованным ответом первым; только то, чего нельзя узнать из
  кода и данных.

## Установка (рабочий компьютер, Windows 11)

1. Скачай этот репозиторий как ZIP (GitHub → Code → Download ZIP) и перенеси на USB.
2. На рабочем компьютере распакуй в любую папку, например `C:\tools\tech-lead-kit\`.
3. **Двойной клик по `install.cmd`** откроет окно установки:
   - таблица проектов: версия, статус («актуально», «обновить до …», «не установлен»), режим
     документов;
   - добавить проекты: «Добавить папку…», **«Найти проекты…»** (папки с `.git` в выбранной
     папке, например `C:\dev`), **«Недавние из VS Code»**, перетаскивание папок в окно или путь
     в строке «Добавить»;
   - «Отметить с обновлением», «Открыть папку», «Убрать из списка», «Удалить kit из проекта»,
     «Что нового»;
   - режим документов: «утверждённые документы сразу становятся частью проекта» (папка `docs`
     и `AGENTS.md`; commit делаешь ты) и папка для документов;
   - кнопка **«Установить / обновить»** ставит или обновляет kit во всех отмеченных проектах.

   Без окна (если PowerShell закрыт политикой) то же самое делается текстом:
   `C:\tools\tech-lead-kit\install.cmd "C:\work\my-project"`. Про режим документов скрипт спросит один раз.
4. Что делает установка:
   - удаляет прежние файлы kit и копирует `kit\.claude\` в `<проект>\.claude\` (свои файлы
     проекта и память `.claude\tl-memory\` не трогает);
   - подключает правила kit через `.claude\CLAUDE.md` (`@tech-lead-kit/CORE.md`). Вместе с ними
     Claude всегда видит памятку `KIT_GUIDE.md`: какие есть команды, когда какую предлагать,
     обычный путь задачи и где лежат документы. Поэтому Claude в проекте знает kit и пользуется им
     сам, даже если ты просто пишешь задачу словами;
   - записывает режим документов в `.claude\tl-memory\publish.json`;
   - прячет файлы kit от git через `.git\info\exclude`: локально, в git ничего не попадает;
   - запоминает проект в `%LOCALAPPDATA%\TechLeadKit\projects.txt`, чтобы при следующем обновлении
     он сразу был в списке.
5. Открой проект в VS Code, начни **новую** сессию Claude Code и запусти `/tl-init`: проверка
   kit, лимиты времени, карта проекта, источники данных, карта документов `KNOWLEDGE.md`. Потом —
   `/tl-go`.

### Проверка, что всё работает
- Набери `/`: должны появиться `/tl-go`, `/tl-init`, `/tl-spec`, `/tl-design`, `/tl-implement`,
  `/tl-sql`, `/tl-review`, `/tl-an`, `/tl-explain`, `/tl-debt`, `/tl-publish`.
- `/memory`: в списке должен быть `.claude/CLAUDE.md` с импортом `CORE.md`.
- `/agents`: должны быть `tl-architect-reviewer`, `tl-sql-reviewer`, `tl-researcher`,
  `tl-an-skeptic`, `tl-spec-skeptic`, `tl-dba`.
- Python для аналитика: `python .claude\skills\tl-analytics\scripts\an_stats.py --selftest`
  должен вывести только строки `ok`.
- `/mcp`: подключены MCP-серверы баз данных проекта (если они есть).
- Запусти `/tl-init`: Claude найдёт источники данных, спросит, какой PROD, а какой TEST, и создаст карту проекта.
  В отчёте будет самопроверка kit. То же отдельно:
  `python .claude\tech-lead-kit\scripts\tl_doctor.py` — 0 ошибок; предупреждения покажут, что ещё
  может работать вместо kit.

Если команды не видны, обнови расширение Claude Code в VS Code. Старые версии поддерживают
не всё.

### Обновление
Перенеси новую версию на USB, дважды кликни `install.cmd` и нажми «Установить / обновить»: все
проекты со старой версией уже отмечены; кнопка «Что нового» показывает изменения. Старые файлы
kit удаляются, новые копируются, память проекта (`.claude\tl-memory\`) остаётся нетронутой.
После обновления запусти `/tl-init` (`/tl-go` напомнит): он обновит карту проекта, источники
данных и `KNOWLEDGE.md`. С 1.x на 2.0: команды `tl-an-learn` и `tl-project-doc` заменены на
`/tl-an learn` и `/tl-explain project`. Версия — `kit/.claude/tech-lead-kit/VERSION`.

### Удаление
```
uninstall.cmd "C:\work\my-project"
```
Удаляет файлы kit и строку импорта. Папка `.claude\tl-memory\` с ADR, дизайнами и реестром
долга **сохраняется**. Опубликованные документы (`docs\`, блок в `AGENTS.md`) принадлежат
проекту и тоже остаются.

## Дополнительная защита баз (по желанию)

Правила безопасности в `CORE.md` — это инструкции для Claude, а не жёсткая блокировка. Сильнее:
- учётная запись агента на PROD — только чтение; DBA может ограничить её ресурсами (SQL Server
  Resource Governor, DB2 RLF `ASUTIME`);
- в `.mcp.json` у сервера базы — `"timeout"` в миллисекундах (для PROD короче);
- в `<проект>\.claude\settings.local.json` — спрашивать разрешение перед каждым вызовом
  сервера базы (имя сервера — из `/mcp`):

```json
{
  "permissions": {
    "ask": ["mcp__<имя-сервера-базы>"]
  }
}
```

Это обычные права доступа, а не hooks. Инструмент записи можно запретить через
`"deny": ["mcp__<имя-сервера>__<tool>"]`.

## Как дорабатывать

- Правила, действующие всегда, лежат в `kit/.claude/tech-lead-kit/CORE.md`. Держи его коротким.
- Знания по теме лежат в `skills/*/SKILL.md` и `references/*.md`. Подробности стоит писать
  в references: они загружаются только когда нужны.
- Стандарты конкретной компании (naming, структура библиотек Natural, шаблон abend-параграфа
  и т.п.) добавляй в соответствующий файл языка в `tl-engineering-standards/references/`.
- Бриф и принятые решения записаны в `docs/BRIEF.md`; аналитик — `docs/ANALYST_DESIGN.md`;
  מנתח מערכות и карта знаний — `docs/SPEC_DESIGN.md`.

## OLEG-SKILL-HESBER: документы-объяснения со схемами

Маршрут `/tl-explain` использует skill `oleg-skill-hesber`. Он делает документы, похожие на путеводитель этого kit: один HTML-файл
со схемами (SVG), светлой и тёмной темой, на иврите справа налево (или на русском/английском
по просьбе). Файл открывается двойным кликом и не обращается в интернет.

Как вызвать:
```
/tl-explain как работает пакетная обработка в модуле Billing
```
или просто «תכין הסבר עם דיאגרמות על ...».

Что делает skill:
1. Собирает факты из кода, конфигураций, ADR и, только на чтение, из базы через MCP. Ничего не выдумывает, а допущения помечает отдельно.
2. Выбирает 2–5 схем: слои и компоненты, шаги, решения и циклы, последовательность вызовов, сравнение.
3. Собирает документ по шаблону `references/template.html`.
4. Для иврита зеркалирует схемы скриптом `scripts/mirror_svg.py` (нужен Python).
5. Сохраняет в `.claude/tl-memory/hesber/<дата>-<тема>.html` или по пути, который ты укажешь.

Имя skill написано строчными буквами (`oleg-skill-hesber`), потому что заглавные буквы в
именах skills не допускаются. Чтобы skill работал во всех проектах, а не только в одном,
скопируй папку `kit\.claude\skills\oleg-skill-hesber` в `%USERPROFILE%\.claude\skills\`.
