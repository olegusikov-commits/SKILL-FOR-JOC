# Tech Lead Kit для Claude Code

Набор файлов для Claude Code (VS Code extension), который заставляет Claude писать код
**как Tech Lead вместе с архитектором**, а не как junior: сначала дизайн и анализ, потом код
малыми шагами, затем независимое ревью.

- Без плагинов и без hooks: только обычные файлы в папке `.claude/` проекта.
- Переносится на USB, ставится одним скриптом `install.cmd` (Windows 11).
- Устанавливается **только в выбранные проекты** и скрыт от git: сам kit в репозиторий
  компании не попадает. В проект попадают только **утверждённые документы**, и только когда ты
  сам их публикуешь (`/tl-publish`).
- Работает с SQL MCP серверами `meet-checkov` и `meet-chequemis`: Claude проверяет **реальную**
  схему, таблицы и индексы, а не угадывает их.

Языки и платформы: C#/.NET, C++, Python, Node.js, COBOL, Natural, микросервисы, web services,
SQL Server 2019/2022, DB2 for z/OS, stored procedures.

> **Путеводитель со схемами:** [`docs/GUIDE.html`](docs/GUIDE.html) (русский) и
> [`docs/GUIDE.he.html`](docs/GUIDE.he.html) (иврит). Открой файл в браузере
> (двойной клик), интернет не нужен. Внутри: общая схема kit, установка и обновление через USB,
> путь задачи SMALL/LARGE, шпаргалка «что писать в какой ситуации» и работа с каждым skill.

## Что внутри

```
kit/.claude/
├── tech-lead-kit/CORE.md          ← базовые правила, загружаются всегда
├── tech-lead-kit/scripts/tl_knowledge.py ← карта знаний и публикация в проект
├── skills/
│   ├── tl-engineering-standards/  ← стандарт кода + файлы по каждому языку
│   ├── tl-architecture/           ← дизайн, границы, API, мейнфрейм, шаблоны ADR
│   ├── tl-sql-engineering/        ← SQL уровня DBA, работа через MCP, SQL Server + DB2 z/OS
│   ├── tl-tech-debt/              ← аудит и реестр технического долга
│   ├── tl-analytics/              ← аналитик: методика, бэктест, статистика, скрипты Python
│   ├── tl-requirements/           ← מנתח מערכות: טופס דרישה, אפיון, таблицы решений, HTML
│   └── oleg-skill-hesber/         ← документы-объяснения со схемами (HTML, иврит/русский)
├── commands/                      ← команды /tl-*
└── agents/
    ├── tl-architect-reviewer.md   ← независимый ревьюер-архитектор
    ├── tl-sql-reviewer.md         ← независимый ревьюер-DBA (только чтение)
    ├── tl-researcher.md           ← исследователь: код / данные / документы (только чтение)
    ├── tl-an-skeptic.md           ← критик выводов аналитика, пересчитывает числа
    └── tl-spec-skeptic.md         ← критик אפיון: проверяет факты по коду и данным
```

При работе в проекте появляется локальная «память» `.claude/tl-memory/`:
`PROJECT_CONTEXT.md` (карта проекта), `KNOWLEDGE.md` (карта всех документов), `spec/`
(אפיונים), `adr/`, `design/`, `TECH_DEBT.md`, `project-doc/` (документ проекта), `analysis/`
(темы и отчёты аналитика).

## Команды

| Команда | Что делает |
|---|---|
| `/tl-init` | Один раз на проект: анализирует проект и базы данных, создаёт `PROJECT_CONTEXT.md` |
| `/tl-spec new <название>` → `/tl-spec SPEC-001` | מנתח מערכות: создаёт טופס דרישה, ты заполняешь что знаешь; затем строит אפיון по коду и данным, проверяет его и **ждёт утверждения** |
| `/tl-spec check <файл>` | Проверка готовой אפיון (md / docx): противоречия, дыры, расплывчатость, данные; отчёт с точными исправлениями |
| `/tl-design <задача>` | Требования → варианты → trade-offs → ADR → **СТОП, ждёт утверждения** |
| `/tl-implement <задача или путь к дизайну>` | Реализация малыми шагами + тесты + самопроверка + ревью |
| `/tl-review [файлы]` | Независимое ревью изменений: архитектор + DBA, находки BLOCKER/MAJOR/MINOR |
| `/tl-sql <задача>` | SQL, процедуры, оптимизация по реальной схеме и индексам через MCP |
| `/tl-debt [путь]` | Аудит технического долга и план его погашения |
| `/oleg-skill-hesber <что объяснить>` | Документ-объяснение со схемами: один HTML-файл, по умолчанию на иврите |
| `/tl-project-doc [модуль] [ru\|en] [html]` | Документ проекта по реальному коду, базам и документам: назначение, архитектура, модули, процессы, модель данных, эксплуатация, риски |
| `/tl-an-learn <тема> [объяснение, документы]` | Аналитик изучает тему (объяснение, документы, код, база), калибрует базовую линию и только потом задаёт вопросы — с предложенными ответами |
| `/tl-an <задача>` | Любая аналитическая задача: как улучшить метрику, оценить идею или код в цифрах, проверить код против задачи, ответить на вопрос по данным |
| `/tl-publish [документы]` | Показывает список утверждённых документов и после «да» переносит их в `docs/` проекта, пишет блок знаний в `AGENTS.md`, чтобы их видели коллеги и любые агенты. Commit делаешь ты |

### Аналитик (`/tl-an`)
Работает по **темам**: всё изученное хранится в `.claude/tl-memory/analysis/<тема>/` и не
изучается заново. Правила: каждое число из сохранённого SQL или скрипта `an_stats.py`;
базовая линия сначала калибруется по известному числу; идеи проверяются бэктестом на истории
(поиск на раннем периоде, подтверждение на позднем); вердикт по верхней границе ошибки
(PASS / FAIL / МАЛО ДАННЫХ); перед выводом независимый критик `tl-an-skeptic` пытается его
опровергнуть. Данные аналитик только читает: сначала TEST, на PROD — по плану запросов, одобренному один раз на тему. Код проекта он не меняет; если нужна реализация — готовит задачу для
`/tl-design`. Документы `.docx/.xlsx/.pptx` читает через `an_doc2text.py` (только стандартный
Python, пакеты не нужны). Подробности: `docs/ANALYST_DESIGN.md`.

### מנתח מערכות (`/tl-spec`)
1. `/tl-spec new <название>` создаёт `טופס דרישה` (`REQUEST.md`). Заполняешь, что знаешь:
   обязателен только раздел 1 «что и зачем». Пустое kit заполнит сам из кода, данных и
   документов и пометит источник каждого пункта (`[מקור: …]`) или `[הנחה]`.
2. `/tl-spec SPEC-001` строит אפיון на иврите: цель с числом, что входит и что **не меняется**,
   требования `REQ`, правила таблицами решений (порядок, точные границы, единицы, «אחרת»),
   термины → поля в базе, кого ещё затронет, сценарии приёмки `AC` с граничными значениями,
   эффект, проверенный на истории. Проверка: `spec_tool.py lint` и критик `tl-spec-skeptic`.
   Результат — `SPEC.md` и красивый `SPEC.html` (офлайн, RTL, тёмная тема, печать, Word его
   открывает). Вопросы — не больше 5, с предложенными ответами. Затем **стоп** до утверждения.
3. После утверждения: `/tl-publish`, затем `/tl-design` (LARGE) или `/tl-implement` (SMALL) —
   каждый AC становится тестом; `/tl-review` и `/tl-an` проверяют код по REQ/AC.

### Знания видны всем агентам
- Каждый документ kit начинается со строки `tl-meta` (тип, статус, дата, **область**: файлы,
  таблицы, термины). Скрипт `tl_knowledge.py index` собирает из них `KNOWLEDGE.md`, и в начале
  **любой** задачи Claude открывает документы своей области. Утверждённая אפיון и принятый ADR
  обязательны: им следуют, или Claude прямо говорит о противоречии.
- `/tl-publish` переносит утверждённые документы в `docs/` проекта (`docs/specs`, `docs/adr`, …)
  и пишет в `AGENTS.md` блок «ידע על הפרויקט» (в `CLAUDE.md` добавляется строка `@AGENTS.md`).
  Так документы видят коллеги без kit и любые агенты (Claude Code, Copilot, Cursor). Черновики,
  рабочие файлы аналитика и сам kit остаются локальными. Commit делаешь ты.

Писать команды не обязательно: правила из `CORE.md` действуют всегда, и Claude сам загружает
нужный skill. Команды просто делают процесс явным и надёжным.

## Правила работы (кратко)

- **Каждая задача классифицируется:** SMALL (баг, мелкая правка) делается сразу; LARGE
  (новый модуль/сервис/endpoint, изменение схемы БД, интеграция, больше 3 файлов) идёт только
  после дизайна и **твоего утверждения**.
- **Язык:** Claude отвечает на русском. Комментарии в коде и документы (אפיון, ADR, дизайн)
  пишутся на иврите. Для исходников мейнфрейма иврит используется только если кодировка его
  поддерживает.
- **SQL MCP:** PROD только на чтение (SELECT по каталогу и маленькие выборки). На TEST изменения
  разрешены, но Claude показывает команду заранее, а для разрушающих операций нужно твоё
  подтверждение. Если среда неизвестна, она считается PROD.

## Установка (рабочий компьютер, Windows 11)

1. Скачай этот репозиторий как ZIP (GitHub → Code → Download ZIP) и перенеси на USB.
2. На рабочем компьютере распакуй в любую папку, например `C:\tools\tech-lead-kit\`.
3. **Двойной клик по `install.cmd`** откроет окно установки:
   - список проектов, где kit уже стоит, с текущей и новой версией;
   - кнопка «Добавить проект…»: выбор папки проекта;
   - режим документов: «утверждённые документы сразу становятся частью проекта» (папка `docs`
     и `AGENTS.md`; commit делаешь ты) и папка для документов;
   - кнопка **«Установить / обновить»** ставит или обновляет kit во всех отмеченных проектах.

   Без окна (если PowerShell закрыт политикой) то же самое делается текстом:
   `C:\tools\tech-lead-kit\install.cmd "C:\work\my-project"`. Про режим документов скрипт спросит один раз.
4. Что делает установка:
   - копирует `kit\.claude\` в `<проект>\.claude\` (существующие файлы проекта не трогает);
   - подключает правила kit через `.claude\CLAUDE.md` (`@tech-lead-kit/CORE.md`). Вместе с ними
     Claude всегда видит памятку `KIT_GUIDE.md`: какие есть команды, когда какую предлагать,
     обычный путь задачи и где лежат документы. Поэтому Claude в проекте знает kit и пользуется им
     сам, даже если ты просто пишешь задачу словами;
   - записывает режим документов в `.claude\tl-memory\publish.json`;
   - прячет файлы kit от git через `.git\info\exclude`: локально, в git ничего не попадает;
   - запоминает проект в `%LOCALAPPDATA%\TechLeadKit\projects.txt`, чтобы при следующем обновлении
     он сразу был в списке.
5. Открой проект в VS Code, начни **новую** сессию Claude Code и запусти `/tl-init`. Он создаёт
   структуру: карту проекта, карту документов `KNOWLEDGE.md` и, в режиме «документы в проекте»,
   `AGENTS.md` с фактами о проекте.

### Проверка, что всё работает
- Набери `/`: должны появиться `/tl-init`, `/tl-spec`, `/tl-design`, `/tl-implement`,
  `/tl-review`, `/tl-sql`, `/tl-debt`, `/tl-project-doc`, `/tl-an-learn`, `/tl-an`, `/tl-publish`.
- `/memory`: в списке должен быть `.claude/CLAUDE.md` с импортом `CORE.md`.
- `/agents`: должны быть `tl-architect-reviewer`, `tl-sql-reviewer`, `tl-researcher`,
  `tl-an-skeptic`, `tl-spec-skeptic`.
- Python для аналитика: `python .claude\skills\tl-analytics\scripts\an_stats.py --selftest`
  должен вывести только строки `ok`.
- `/mcp`: должны быть подключены `meet-checkov` и `meet-chequemis`.
- Запусти `/tl-init`: Claude спросит, какой сервер PROD, а какой TEST, и создаст карту проекта.

Если команды не видны, обнови расширение Claude Code в VS Code. Старые версии поддерживают
не всё.

### Обновление
Перенеси новую версию на USB, дважды кликни `install.cmd` и нажми «Установить / обновить»: все
проекты со старой версией уже отмечены. Файлы kit обновятся,
память проекта (`.claude\tl-memory\`) останется нетронутой. После обновления запусти `/tl-init`:
он обновит карту проекта и карту знаний `KNOWLEDGE.md` и добавит строку `tl-meta` документам,
созданным старой версией (с 1.2 на 1.3 это обязательно). Версия указана в
`kit/.claude/tech-lead-kit/VERSION`.

### Удаление
```
uninstall.cmd "C:\work\my-project"
```
Удаляет файлы kit и строку импорта. Папка `.claude\tl-memory\` с ADR, дизайнами и реестром
долга **сохраняется**. Опубликованные документы (`docs\`, блок в `AGENTS.md`) принадлежат
проекту и тоже остаются.

## Дополнительная защита MCP (по желанию)

Правила безопасности MCP в `CORE.md` — это инструкции для Claude, а не жёсткая блокировка.
PROD уже защищён на уровне базы (только SELECT). Если хочешь, чтобы Claude Code **спрашивал
разрешение перед каждым вызовом** SQL MCP, добавь в `<проект>\.claude\settings.local.json`:

```json
{
  "permissions": {
    "ask": ["mcp__meet-checkov", "mcp__meet-chequemis"]
  }
}
```

Это обычные права доступа, а не hooks. Когда узнаешь в `/mcp` точные названия инструментов
сервера, можно запретить конкретный инструмент записи через `"deny": ["mcp__meet-checkov__<tool>"]`.

## Как дорабатывать

- Правила, действующие всегда, лежат в `kit/.claude/tech-lead-kit/CORE.md`. Держи его коротким.
- Знания по теме лежат в `skills/*/SKILL.md` и `references/*.md`. Подробности стоит писать
  в references: они загружаются только когда нужны.
- Стандарты конкретной компании (naming, структура библиотек Natural, шаблон abend-параграфа
  и т.п.) добавляй в соответствующий файл языка в `tl-engineering-standards/references/`.
- Бриф и принятые решения записаны в `docs/BRIEF.md`; аналитик — `docs/ANALYST_DESIGN.md`;
  מנתח מערכות и карта знаний — `docs/SPEC_DESIGN.md`.

## OLEG-SKILL-HESBER: документы-объяснения со схемами

Skill `oleg-skill-hesber` делает документы, похожие на путеводитель этого kit: один HTML-файл
со схемами (SVG), светлой и тёмной темой, на иврите справа налево (или на русском/английском
по просьбе). Файл открывается двойным кликом и не обращается в интернет.

Как вызвать:
```
/oleg-skill-hesber объясни, как работает пакетная обработка чеков в модуле Billing
```
или просто «תכין הסבר עם דיאגרמות על ...».

Что делает skill:
1. Собирает факты из кода, конфигураций, ADR и, только на чтение, из базы через MCP. Ничего не выдумывает, а допущения помечает отдельно.
2. Выбирает 2–5 схем: слои и компоненты, шаги, решения и циклы, последовательность вызовов, сравнение.
3. Собирает документ по шаблону `references/template.html`.
4. Для иврита зеркалирует схемы скриптом `scripts/mirror_svg.py` (нужен Python).
5. Сохраняет в `.claude/tl-memory/hesber/<дата>-<тема>.html` или по пути, который ты укажешь.

Имя skill написано строчными буквами (`oleg-skill-hesber`), потому что заглавные буквы в
именах skills не допускаются. Чтобы skill работал во всех проектах, а не только в одном,
скопируй папку `kit\.claude\skills\oleg-skill-hesber` в `%USERPROFILE%\.claude\skills\`.
