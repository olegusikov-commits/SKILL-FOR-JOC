# Tech Lead Kit для Claude Code

Набор файлов для Claude Code (VS Code extension), который заставляет Claude писать код
**как Tech Lead вместе с архитектором**, а не как junior: сначала дизайн и анализ, потом код
малыми шагами, затем независимое ревью.

- Без плагинов и без hooks: только обычные файлы в папке `.claude/` проекта.
- Переносится на USB, ставится одним скриптом `install.cmd` (Windows 11).
- Устанавливается **только в выбранные проекты** и скрыт от git: в репозиторий компании
  ничего не попадает.
- Работает с SQL MCP серверами `meet-checkov` и `meet-chequemis`: Claude проверяет **реальную**
  схему, таблицы и индексы, а не угадывает их.

Языки и платформы: C#/.NET, C++, Python, Node.js, COBOL, Natural, микросервисы, web services,
SQL Server 2019/2022, DB2 for z/OS, stored procedures.

> **Путеводитель со схемами:** [`docs/GUIDE.html`](docs/GUIDE.html) (русский) и
> [`docs/GUIDE.he.html`](docs/GUIDE.he.html) (иврит). Открой файл в браузере
> (двойной клик), интернет не нужен. Внутри: общая схема kit, установка и обновление через USB,
> путь задачи SMALL/LARGE, шпаргалка «что писать в какой ситуации» и работа с каждым skill.

## Что внутри

```
kit/.claude/
├── tech-lead-kit/CORE.md          ← базовые правила, загружаются всегда
├── skills/
│   ├── tl-engineering-standards/  ← стандарт кода + файлы по каждому языку
│   ├── tl-architecture/           ← дизайн, границы, API, мейнфрейм, шаблоны ADR
│   ├── tl-sql-engineering/        ← SQL уровня DBA, работа через MCP, SQL Server + DB2 z/OS
│   ├── tl-tech-debt/              ← аудит и реестр технического долга
│   └── oleg-skill-hesber/         ← документы-объяснения со схемами (HTML, иврит/русский)
├── commands/                      ← команды /tl-*
└── agents/
    ├── tl-architect-reviewer.md   ← независимый ревьюер-архитектор
    └── tl-sql-reviewer.md         ← независимый ревьюер-DBA (только чтение)
```

При работе в проекте появляется локальная «память» `.claude/tl-memory/`:
`PROJECT_CONTEXT.md` (карта проекта), `adr/`, `design/`, `TECH_DEBT.md`.

## Команды

| Команда | Что делает |
|---|---|
| `/tl-init` | Один раз на проект: анализирует проект и базы данных, создаёт `PROJECT_CONTEXT.md` |
| `/tl-design <задача>` | Требования → варианты → trade-offs → ADR → **СТОП, ждёт утверждения** |
| `/tl-implement <задача или путь к дизайну>` | Реализация малыми шагами + тесты + самопроверка + ревью |
| `/tl-review [файлы]` | Независимое ревью изменений: архитектор + DBA, находки BLOCKER/MAJOR/MINOR |
| `/tl-sql <задача>` | SQL, процедуры, оптимизация по реальной схеме и индексам через MCP |
| `/tl-debt [путь]` | Аудит технического долга и план его погашения |
| `/oleg-skill-hesber <что объяснить>` | Документ-объяснение со схемами: один HTML-файл, по умолчанию на иврите |

Писать команды не обязательно: правила из `CORE.md` действуют всегда, и Claude сам загружает
нужный skill. Команды просто делают процесс явным и надёжным.

## Правила работы (кратко)

- **Каждая задача классифицируется:** SMALL (баг, мелкая правка) делается сразу; LARGE
  (новый модуль/сервис/endpoint, изменение схемы БД, интеграция, больше 3 файлов) идёт только
  после дизайна и **твоего утверждения**.
- **Язык:** Claude отвечает на русском. Комментарии в коде и документы (ADR, дизайн) пишутся
  на иврите. Для исходников мейнфрейма иврит используется только если кодировка его
  поддерживает.
- **SQL MCP:** PROD только на чтение (SELECT по каталогу и маленькие выборки). На TEST изменения
  разрешены, но Claude показывает команду заранее, а для разрушающих операций нужно твоё
  подтверждение. Если среда неизвестна, она считается PROD.

## Установка (рабочий компьютер, Windows 11)

1. Скачай этот репозиторий как ZIP (GitHub → Code → Download ZIP) и перенеси на USB.
2. На рабочем компьютере распакуй в любую папку, например `C:\tools\tech-lead-kit\`.
3. Запусти для нужного проекта:
   ```
   C:\tools\tech-lead-kit\install.cmd "C:\work\my-project"
   ```
   Или двойной клик по `install.cmd`: скрипт спросит путь.
4. Скрипт:
   - копирует `kit\.claude\` в `<проект>\.claude\` (существующие файлы проекта не трогает);
   - создаёт `.claude\CLAUDE.md` со строкой `@tech-lead-kit/CORE.md` или добавляет эту строку
     в уже существующий файл;
   - добавляет файлы kit в `.git\info\exclude`. Это локальное исключение, в git ничего не коммитится.
5. Открой проект в VS Code и начни **новую** сессию Claude Code.

### Проверка, что всё работает
- Набери `/`: должны появиться `/tl-init`, `/tl-design`, `/tl-implement`, `/tl-review`,
  `/tl-sql`, `/tl-debt`.
- `/memory`: в списке должен быть `.claude/CLAUDE.md` с импортом `CORE.md`.
- `/agents`: должны быть `tl-architect-reviewer` и `tl-sql-reviewer`.
- `/mcp`: должны быть подключены `meet-checkov` и `meet-chequemis`.
- Запусти `/tl-init`: Claude спросит, какой сервер PROD, а какой TEST, и создаст карту проекта.

Если команды не видны, обнови расширение Claude Code в VS Code. Старые версии поддерживают
не всё.

### Обновление
Перенеси новую версию на USB и снова запусти `install.cmd` для проекта. Файлы kit обновятся,
память проекта (`.claude\tl-memory\`) останется нетронутой. Версия указана в
`kit/.claude/tech-lead-kit/VERSION`.

### Удаление
```
uninstall.cmd "C:\work\my-project"
```
Удаляет файлы kit и строку импорта. Папка `.claude\tl-memory\` с ADR, дизайнами и реестром
долга **сохраняется**.

## Дополнительная защита MCP (по желанию)

Правила безопасности MCP в `CORE.md` — это инструкции для Claude, а не жёсткая блокировка.
PROD уже защищён на уровне базы (только SELECT). Если хочешь, чтобы Claude Code **спрашивал
разрешение перед каждым вызовом** SQL MCP, добавь в `<проект>\.claude\settings.local.json`:

```json
{
  "permissions": {
    "ask": ["mcp__meet-checkov", "mcp__meet-chequemis"]
  }
}
```

Это обычные права доступа, а не hooks. Когда узнаешь в `/mcp` точные названия инструментов
сервера, можно запретить конкретный инструмент записи через `"deny": ["mcp__meet-checkov__<tool>"]`.

## Как дорабатывать

- Правила, действующие всегда, лежат в `kit/.claude/tech-lead-kit/CORE.md`. Держи его коротким.
- Знания по теме лежат в `skills/*/SKILL.md` и `references/*.md`. Подробности стоит писать
  в references: они загружаются только когда нужны.
- Стандарты конкретной компании (naming, структура библиотек Natural, шаблон abend-параграфа
  и т.п.) добавляй в соответствующий файл языка в `tl-engineering-standards/references/`.
- Бриф и принятые решения записаны в `docs/BRIEF.md`.

## OLEG-SKILL-HESBER: документы-объяснения со схемами

Skill `oleg-skill-hesber` делает документы, похожие на путеводитель этого kit: один HTML-файл
со схемами (SVG), светлой и тёмной темой, на иврите справа налево (или на русском/английском
по просьбе). Файл открывается двойным кликом и не обращается в интернет.

Как вызвать:
```
/oleg-skill-hesber объясни, как работает пакетная обработка чеков в модуле Billing
```
или просто «תכין הסבר עם דיאגרמות על ...».

Что делает skill:
1. Собирает факты из кода, конфигураций, ADR и, только на чтение, из базы через MCP. Ничего не выдумывает, а допущения помечает отдельно.
2. Выбирает 2–5 схем: слои и компоненты, шаги, решения и циклы, последовательность вызовов, сравнение.
3. Собирает документ по шаблону `references/template.html`.
4. Для иврита зеркалирует схемы скриптом `scripts/mirror_svg.py` (нужен Python).
5. Сохраняет в `.claude/tl-memory/hesber/<дата>-<тема>.html` или по пути, который ты укажешь.

Имя skill написано строчными буквами (`oleg-skill-hesber`), потому что заглавные буквы в
именах skills не допускаются. Чтобы skill работал во всех проектах, а не только в одном,
скопируй папку `kit\.claude\skills\oleg-skill-hesber` в `%USERPROFILE%\.claude\skills\`.
