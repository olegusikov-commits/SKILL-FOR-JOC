# Обучение kit в проекте: архитектура и решения

> Реализовано в kit 2.4.0 (`/tl-retro`, `tl_learn.py`). Перед реализацией план прошёл независимое
> ревью (вердикт «переделать узко»), все замечания учтены — раздел 6.

---

## 1. Задача
Kit в проекте ничего не помнил о своей работе: каждая новая сессия повторяла те же ошибки, заново
спрашивала то, на что владелец уже отвечал, не знала его терминов и стиля. Нужно, чтобы kit:
- учился на своих ошибках и поправках пользователя;
- учил язык пользователя: **термины и жаргон**, **стиль общения**, **привычки работы**;
- сам строил skill или менял порядок работы, когда видит повторяющуюся работу;
- с каждой задачей лучше подходил проекту и человеку.

## 2. Решения владельца
| Вопрос | Решение |
|---|---|
| Hooks | **Без hooks.** Сбор идёт по правилам kit и из того, что уже лежит на диске |
| Кто утверждает | **Kit предлагает — владелец утверждает** кнопками. Без вопроса — только длина, формат ответа и язык чата, о которых пользователь попросил прямо |
| Чему учиться | Термины и жаргон, стиль общения, привычки работы, свои ошибки |
| Где живёт | **Локально + публикация**: `.claude/tl-memory/learn/` (вне git, обновление kit не трогает); команде — только глоссарий |
| Skills проекта | **Настоящие skills сейчас** (`.claude/skills/tlp-*`), а не «рецепты» в памяти |

## 3. Как устроено

| Слой | Где | Что |
|---|---|---|
| Сырьё | `learn/INBOX.md` | одна строка — одно наблюдение: дата · вид · область · что случилось · источник |
| Утверждённое | `learn/LESSONS.md` | уроки `L-nnn` (`active` / `rejected` / `retired`, область: `kit`, `project`, `route:`, `skill:`, `agent:`, `area:`) |
| | `learn/PROFILE.md` | человек: общение, привычки, постоянные ответы (≤ 12 пунктов) |
| | `learn/GLOSSARY.md` | термин → смысл → где в коде и данных (иврит; публикуется) |
| | `.claude/skills/tlp-*/` | skills проекта для работы, повторённой 3+ раза |
| В контексте | `learn/ACTIVE.md` | генерируется, ≤ 60 строк; `CORE.md` импортирует его сразу после `KIT_GUIDE.md` |

Цикл:
1. **Наблюдение.** Правило в KIT_GUIDE «Learning» и пункт Definition of Done: поправка, своя ошибка
   (BLOCKER в своём коде, красный тест после «готово»), незнакомый термин, просьба о стиле, повтор
   выбора или шагов, помеха со стороны kit → `tl_learn.py note`. `note` сам говорит, когда пора разбирать.
2. **Сбор пропущенного** (`harvest`): история сессий Claude Code этого проекта
   (`~/.claude/projects/<проект>/*.jsonl` — поправки, причина отказа от действия, сообщение после
   прерывания), заметки встроенной auto memory, упавшие и зависшие запросы из `sql-journal.csv`,
   одинаковый ответ на один вопрос в нескольких אפיונים.
3. **Разбор** `/tl-retro`: группировка, отсев (разовое, уже записанное, ослабляющее CORE, ранее
   отклонённое без новых доказательств), до 8 предложений кнопками.
4. **Применение:** `render` собирает `ACTIVE.md`; со следующего сообщения он в контексте основного
   разговора и агентов kit (они загружают CLAUDE.md).

## 4. Защита
- **CORE главнее.** Урок может только добавить или сузить правило. `lint` отклоняет уроки, которые
  разрешают пропускать тесты, стандарты или утверждение, делать commit/push, писать на PROD; урок,
  который касается правила CORE без запрета, получает предупреждение. Шапка `ACTIVE.md` повторяет: CORE wins.
- **Без секретов и персональных данных:** `note` и `harvest` не записывают пароли, строки
  подключения, e-mail, номера (9+ цифр, телефоны); `lint` проверяет все файлы памяти и skills проекта.
- **Одно событие — доказательство, а не правило:** предложение показывает «видели N×», решает человек.
- **Бюджеты:** ≤ 30 активных уроков, ≤ 12 пунктов профиля, `ACTIVE.md` ≤ 60 строк; термины, которые не
  помещаются, остаются в глоссарии со ссылкой.
- **Устаревание:** урок со ссылкой на файл, которого больше нет, `lint` помечает; `/tl-retro`
  предлагает списать.
- **Конкурент:** встроенная auto memory Claude Code пишет заметки без утверждения. `tl_doctor`
  предупреждает, `/tl-init` выключает её в личном `.claude/settings.local.json` проекта
  (`autoMemoryEnabled: false`); уже записанные ею заметки собирает `harvest`.
- **Агентам kit** поле `memory:` не дано: оно дало бы read-only агентам запись без утверждения.

## 5. Skills проекта `tlp-*`
- Создаются только через `/tl-retro` по шаблону `kit/.claude/tech-lead-kit/templates/project-skill.md`,
  с источниками (из каких наблюдений) и `tl-meta`.
- Считаются skills kit: CORE «Kit tools first» и `tl_doctor` (`is_kit_name`) их не отвергают.
- Обновление kit удаляет только `tl-*` (маска `tl-*` не совпадает с `tlp-*`, и с 8.3-именем тоже);
  удаление kit переносит их в `tl-memory/skills-disabled/` (без kit они ссылались бы на удалённые
  скрипты), следующая установка возвращает. Скрыты от git (`.claude/skills/tlp-*/`).

## 6. Что изменило ревью плана
| Было в плане | Стало | Почему |
|---|---|---|
| `tl_learn.py brief` в начале каждой задачи | `ACTIVE.md`, импортированный в CORE | шаг «прочитай в начале» пропускают (видно в демо); импорт работает всегда, без вызова инструмента, и у агентов |
| overlays для каждого skill и агента | одна строка с областью в `ACTIVE.md` | 13 правок файлов, лишние чтения в бюджете `maxTurns` |
| публикация уроков через `/tl-publish` | публикуется только глоссарий | `publish` переносит файл — уроки исчезли бы из памяти; уроки о поведении kit команде без kit не нужны |
| `/tl-learn` | `/tl-retro` | путался с `/tl-an learn` |
| `REJECTED.md`, `KIT_FEEDBACK.md`, `stats` | статусы `rejected` и область `kit` в `LESSONS.md` | меньше файлов, тот же результат |
| сбор только по правилу | правило + `harvest` из истории сессий и журналов | одно правило модель забывает; история на диске уже есть |
| правки в 5 командах | один пункт Definition of Done + раздел KIT_GUIDE | один источник правила |

## 7. Проверка
- `tests/test_tl_learn.py`: note (форматы, секреты, дубликаты, подсказка), render (файлы с `tl-meta`,
  бюджет, глоссарий после публикации), lint (ослабление CORE, сужение разрешено, бюджеты, skills
  проекта, устаревшие пути), harvest (иврит целыми словами, отказ с причиной, прерывание, системные
  сообщения не считаются, SQL, ответы в אפיונים, auto memory, поиск истории по `cwd`).
- `tests/test_kit_structure.py`: импорт `ACTIVE.md`, раздел «Learning», `tlp-*` в установщике и
  деинсталляторе. `tests/test_tl_doctor.py`: auto memory, `tlp-*` не чужие, проблемы памяти.
- Демо: сценарии `retro` → `retro-next` (`demo/README.md`).
- Вручную на Windows: обновление kit сохраняет `tl-memory` и `tlp-*`; `/memory` показывает
  `ACTIVE.md`; удаление и установка возвращают skills проекта.
