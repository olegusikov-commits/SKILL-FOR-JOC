## Допущения
- Д-1: порог 2% относится к доле ошибок среди НОВЫХ авто-одобрений (дельта к текущим правилам), оценка по верхней границе 95%. Влияет на все выводы о «можно/нельзя».
- Д-2: «ошибка» = итог проверки REJECTED либо APPROVED с исправлением суммы. `risk_flag` не используется (ставится после решения, сильно коррелирует с отказом). Если исправление суммы не считается ошибкой, допустимая зона шире.
- Д-3: финальная проверка = последняя по `reviewed_at DESC, review_id DESC` (в 491 чеке две проверки, в 115 из них решения противоречат).
- Д-4: `payer_prev_cheques` берём как есть (известно при решении), хотя пересчитать его из cheques нельзя.
- Д-5: данные TEST; считаю их отражающими PROD по структуре. Идеально ровные 4 000 чеков в месяц похожи на синтетику — выводы о бизнесе по этим числам условны.
- Д-6: решение פקיד по TO_CLERK-чекам = истина для backtest; перенос на чеки, которые сейчас авто-одобряются, не проверяем (смещение отбора).
- Д-7: ACCOUNT_BLOCKED и DUPLICATE_SUSPECT — жёсткие остановки, не ослабляем.
- План запросов одобрен пользователем 2026-10-17 (среда TEST, SQLite, SELECT, агрегаты по ≤36 000 строкам: baseline по месяцам, воронки, сегментные срезы, backtest). Новая таблица, больший период или PROD — спросить заново.
